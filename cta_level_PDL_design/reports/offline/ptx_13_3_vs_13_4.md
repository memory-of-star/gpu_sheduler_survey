# CUDA 13.3 vs 13.4：PDL PTX Lowering 对比实验报告

日期：2026-08-04  
目标架构：`sm_103`（B300/GB300 编译目标）  
实验状态：**有效的离线编译产物对比；没有连接 GPU，不是运行时或性能实验**

## 1. 执行摘要

四个 PDL CUDA source 分别用 nvcc 13.3.33 和 13.4.46 编译为 `sm_103` PTX，共生成 8 个 PTX 文件。

结果：

- CUDA 13.3 输出 PTX ISA 9.3；CUDA 13.4 输出 PTX ISA 9.4。
- 8 个文件都各含一条 `griddepcontrol.launch_dependents` 和一条 `griddepcontrol.wait`。
- 四组 13.3→13.4 diff 完全同型：compiler header/PTX version 改变，producer predicate 代码少一条冗余 `setp`，PDL 指令本身不变。
- 13.3 文件为 91 行，13.4 文件为 90 行。
- same-stream、cross-stream 和 CUDA Graph 的差异属于 host launch metadata，不会改变这两个 device kernel 的 PTX。

结论：**在这四个最小样例中，CUDA 13.4 没有把公开 PDL intrinsic lowering 成新的 tile/sub-grid 指令，仍然是相同的 grid-level `griddepcontrol`。**

## 3. 四个 source case

| Source | 目的 |
|---|---|
| `pdl_demo.cu` | 手写与 runtime intrinsic 等价的 inline `griddepcontrol` |
| `pdl_demo_real.cu` | 使用真实 CUDA device intrinsics |
| `pdl_streams.cu` | 同 device kernels，host 展示 same/cross-stream launch |
| `pdl_graph.cu` | 同 device kernels，host 构造 programmatic Graph edge |

四个 source 的 host 部分不同，但 producer/consumer device kernels 的核心相同。

| Case | CUDA 13.3 lines | CUDA 13.4 lines | launch_dependents | wait |
|---|---:|---:|---:|---:|
| pdl_demo | 91 | 90 | 1/1 | 1/1 |

`1/1` 表示 13.3 与 13.4 各一条。

## 5. 实际 PTX 指令

Producer：

~~~ptx
griddepcontrol.launch_dependents;
~~~

Consumer：

~~~ptx
griddepcontrol.wait;
~~~

这两条指令在两个 toolkit 输出中没有语法变化。

## 6. 13.3→13.4 diff

四个 case 的 diff 都只有以下类型：

1. Compiler Build ID 从 CL-37862127 变为 CL-38501229；
2. toolkit header 从 13.3/V13.3.33 变为 13.4/V13.4.46；
3. `.version 9.3` 变为 `.version 9.4`；
4. predicate register 数从 `%p<3>` 变为 `%p<2>`；
5. 13.4 删除一条重复的 `setp.ge.s32`，复用已有 predicate；
6. `griddepcontrol.launch_dependents` 和 `griddepcontrol.wait` 不变。

因此少一行来自普通 compiler optimization，不是 PDL 语义或粒度变化。

## 7. 为什么 stream/graph 不出现在 PTX 中

same-stream、cross-stream 和 Graph programmatic dependency 由 host API 表达：

- `cudaLaunchAttributeProgrammaticStreamSerialization`；
- `cudaLaunchAttributeProgrammaticEvent`；
- `cudaGraphDependencyTypeProgrammatic` edge data。

`nvcc -ptx` 为 device kernels 生成 PTX，不会把 host-side graph topology 或 stream event 写入 kernel PTX。因此 `pdl_streams` 和 `pdl_graph` 的 device PTX 与最小 demo 相同是预期结果。

## 8. 能成立的结论

本实验支持：

1. nvcc 13.3 和 13.4 都把两个 PDL device intrinsics lowering 为 grid-level `griddepcontrol`。
2. 四个样例中没有出现 tile-level/sub-grid readiness 指令。
3. CUDA 13.4 的可见代码差异是 PTX version/header 和一处普通 predicate 优化。
4. stream/graph 差异必须从 host metadata 和 runtime 行为研究，不能只看 device PTX。

## 9. 不能成立的结论

本实验不支持：

1. CUDA 13.4 runtime/driver 与 13.3 性能相同。
2. SASS 或未公开硬件行为完全没有变化；本轮只比较 PTX。
3. B300 真机运行结果；编译容器没有 GPU/driver。
4. CLC lowering 的版本对比；四个 source 只覆盖 PDL。
5. 未来 toolkit 不会加入更细粒度接口。
